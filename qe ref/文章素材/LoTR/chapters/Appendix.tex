\section{Overall LoTR Pipeline}
\label{app:alg_pipeline}

This section makes the end-to-end realization of LoTR explicit. LoTR is a two-stage plug-in system: offline logic modeling followed by online sentence-level pathway routing under a fixed external reasoning strategy \(\pi\). The appendix does not introduce additional modeling objects; it only makes the runtime pipeline and artifact boundary explicit.

\begin{algorithm}[b]
\caption{LoTR: End-to-End Pipeline}
\label{alg:lotr_pipeline}
\begin{algorithmic}[1]
\REQUIRE Frozen backbone \(f_\theta\), pooled trajectory set \(\mathcal{D}=\{(p,y_{1:T},\pi)\}\), routed layers \(\mathcal{L}_{\mathrm{route}}\), test inputs \(\mathcal{X}\)
\ENSURE Offline artifact \(\mathcal{A}=\{\{c_k\}_{k=1}^K,\{A^{(\ell)},b^{(\ell)}\}_{\ell\in\mathcal{L}_{\mathrm{route}}},\{M_k\}_{k=1}^K\}\), routed reasoning outputs
\STATE \textbf{Offline stage (once per backbone)}
\STATE \quad Build pooled sentence-level readout bank \(\mathcal{R}=\{r_t\}\) from trajectories in \(\mathcal{D}\)
\STATE \quad Cluster \(\mathcal{R}\) into \(K\) recurring logic states; obtain centroids \(\{c_k\}_{k=1}^K\)
\STATE \quad Construct soft targets \(\alpha_t^\star\) and fit layer-wise probes \(q_t^{(\ell)}\)
\STATE \quad Estimate state-conditioned head importance \(I_{\ell,h,k}\) and cache templates \(M_k=\{m_k^{(\ell,h)}\}\)
\STATE \quad Save artifact \(\mathcal{A}\)
\STATE \textbf{Online stage (for each \(x\in\mathcal{X}\) under fixed strategy \(\pi\))}
\STATE \quad Initialize the paradigm-specific prompt and begin sentence-level generation
\FOR{each completed reasoning sentence step \(t\)}
    \STATE Read layer-wise sentence readouts \(r_t^{(\ell)}\) at routed layers
    \STATE Infer logic activations \(q_t^{(\ell)}\) using the cached probes
    \STATE Compose routed coefficients \(\gamma_{t+1}^{(\ell,h)}=\mathrm{clip}\!\left(\sum_k q_t^{(\ell)}(k)m_k^{(\ell,h)},0,1\right)\)
    \STATE Instantiate the pathway \(\mathcal{P}_{t+1}\) and generate the next reasoning sentence
\ENDFOR
\STATE Return the routed trajectory, final answer, and routing diagnostics
\end{algorithmic}
\end{algorithm}

Algorithm~\ref{alg:lotr_pipeline} is a direct algorithmic restatement of Sec.~\ref{sec:lotr}: LoTR does not replace the external reasoning strategy \(\pi\), but improves step-level internal execution by instantiating pathway coefficients \(\gamma\) according to the current logic activations.

\subsection{Trajectory Pooling and Sentence-Level Readout Interface}
\label{app:alg_pipeline_readout}

To keep the controller reusable across reasoning paradigms, LoTR first converts all collected trajectories into a unified sentence-level readout bank. The readout interface follows Sec.~\ref{sec:offline}:
\begin{equation}
r_t=\phi(p,y_{\le t};f_\theta)\in\mathbb{R}^d.
\label{eq:app_readout_interface}
\end{equation}
Each bank entry pairs a readout \(r_t\) with its outer paradigm \(\pi\), and clustering plus probe fitting operate on this paradigm-pooled bank.

\paragraph{Sentence boundary convention.}
Online routing is triggered only when a sentence boundary is reached, e.g., a newline or other configured delimiter. This matches the sentence-level control granularity in Sec.~\ref{sec:online}, avoids token-level oscillation, and keeps probe invocation lightweight.

\paragraph{Artifact boundary.}
The offline stage outputs one reusable artifact:
\begin{equation}
\mathcal{A}=\{\{c_k\}_{k=1}^K,\ \{A^{(\ell)},b^{(\ell)}\}_{\ell\in\mathcal{L}_{\mathrm{route}}},\ \{M_k\}_{k=1}^K\},
\label{eq:app_artifact_bundle}
\end{equation}
which is reused by all online runs on the same backbone. Offline choices such as the selected \(K\), soft-target temperature \(\tau\), and routed-layer set \(\mathcal{L}_{\mathrm{route}}\) are fixed at compile time; backbone weights remain frozen throughout.

\section{Offline Algorithm}
\label{app:alg_offline}

This section details how LoTR compiles a shared logic basis and corresponding pathway templates from pooled trajectories. The offline stage uses one unified sentence-level readout bank, one shared clustering space, and one layer-wise probe family, all tied to the same frozen backbone.

\begin{algorithm}[t]
\caption{LoTR Offline Compilation}
\label{alg:lotr_offline}
\begin{algorithmic}[1]
\REQUIRE Pooled trajectory set \(\mathcal{D}\), frozen backbone \(f_\theta\), routed layers \(\mathcal{L}_{\mathrm{route}}\), \(K\)-search range \([K_{\min},K_{\max}]\), temperature \(\tau\)
\ENSURE Centroids \(\{c_k\}_{k=1}^K\), trained probe parameters \(\{A^{(\ell)},b^{(\ell)}\}_{\ell\in\mathcal{L}_{\mathrm{route}}}\), pathway templates \(\{M_k\}_{k=1}^K\), reusable artifact \(\mathcal{A}\)
\STATE \textbf{Step 1: Build sentence-level readout bank}
\FOR{each trajectory step \(t\) in \(\mathcal{D}\)}
    \STATE Extract sentence readout \(r_t=\phi(p,y_{\le t};f_\theta)\)
    \STATE Store readout \(r_t\) with paradigm label \(\pi\)
\ENDFOR
\STATE \textbf{Step 2: Logic-state discovery}
\STATE Run clustering on \(\mathcal{R}=\{r_t\}\), sweep \(K\in[K_{\min},K_{\max}]\), and select \(K\) by clustering quality
\STATE Obtain centroids \(\{c_k\}_{k=1}^K\), cluster assignments \(\{\mathcal{C}_k\}_{k=1}^K\), and effective radii \(\{d_k\}_{k=1}^K\)
\STATE \textbf{Step 3: Soft state targets}
\FOR{each stored step \(t\)}
    \STATE Compute \(\alpha_t^\star(k)\propto\exp(-\|r_t-c_k\|_2^2/(\tau d_k^2))\)
\ENDFOR
\STATE \textbf{Step 4: Probe fitting}
\FOR{each routed layer \(\ell\in\mathcal{L}_{\mathrm{route}}\)}
    \STATE Extract layer-wise sentence readouts \(r_t^{(\ell)}\)
    \STATE Fit sigmoid probe \(q_t^{(\ell)}=\sigma(A^{(\ell)}r_t^{(\ell)}+b^{(\ell)})\)
\ENDFOR
\STATE \textbf{Step 5: Template construction}
\FOR{each state \(k\)}
    \STATE Estimate \(I_{\ell,h,k}\) from head outputs on samples in \(\mathcal{C}_k\)
    \STATE Normalize within each layer to obtain \(M_k=\{m_k^{(\ell,h)}\}_{(\ell,h)\in\mathcal{H}}\)
\ENDFOR
\STATE Save artifact \(\mathcal{A}\leftarrow\{\{c_k\},\{A^{(\ell)},b^{(\ell)}\},\{M_k\}\}\)
\end{algorithmic}
\end{algorithm}

\paragraph{Implementation alignment.}
Algorithm~\ref{alg:lotr_offline} is a direct expansion of Sec.~\ref{sec:offline}: sentence-level readout extraction, pooled clustering with quality-based \(K\) selection, soft state targets, layer-wise probe fitting, and template caching for online reuse.

\subsection{Cluster Selection and Soft Target Construction}
\label{app:alg_offline_cluster}

Let \(\mathcal{R}=\{r_t\}_{t=1}^N\). We sweep \(K\in[K_{\min},K_{\max}]\), run clustering, and select the final \(K\) by a clustering-quality criterion. With centroids \(\{c_k\}\), assignments \(\{\mathcal{C}_k\}\), and effective radii \(\{d_k\}\), we construct soft state targets by Eq.~\eqref{eq:lotr_soft_target}. In practice, the targets are used directly in BCE probe fitting without imposing simplex normalization, so that a step may remain simultaneously aligned with multiple recurring states.

\subsection{Layer-Wise Probe Fitting and Template Caching}
\label{app:alg_offline_probe_template}

For each routed layer \(\ell\in\mathcal{L}_{\mathrm{route}}\), we fit probe outputs by Eq.~\eqref{eq:lotr_probe} using the objective in Eq.~\eqref{eq:lotr_probe_loss}. Then, for each state \(k\), we estimate \(I_{\ell,h,k}\) by Eq.~\eqref{eq:lotr_importance} and normalize within each layer to obtain \(m_k^{(\ell,h)}\in[0,1]\). The resulting cached template family \(\{M_k\}_{k=1}^K\) is consumed directly by the online routing rule in Eq.~\eqref{eq:lotr_routing}.

\paragraph{Complexity summary.}
Offline complexity is dominated by (i) clustering over \(N\) sentence-level readouts and (ii) state-conditioned head-importance estimation over pooled trajectory steps. Online complexity at each sentence boundary is dominated by one probe forward per routed layer plus one template mixture, namely
\begin{equation}
O\!\left(|\mathcal{L}_{\mathrm{route}}|K+\sum_{\ell\in\mathcal{L}_{\mathrm{route}}} H_\ell K\right).
\end{equation}
This is small relative to the cost of the wrapped backbone forward pass, which is why LoTR adds only lightweight overhead at runtime.

\section{Online Algorithm}
\label{app:alg_online}

This section details runtime LoTR inference under any fixed external reasoning paradigm \(\pi\). Online LoTR does not modify the external reasoning policy itself; it only updates the internal pathway at sentence boundaries using the cached offline artifact.

\begin{algorithm}[t]
\caption{LoTR Online Sentence-Level Routing}
\label{alg:lotr_online}
\begin{algorithmic}[1]
\REQUIRE Frozen backbone \(f_\theta\), offline artifact \(\mathcal{A}\), fixed reasoning strategy \(\pi\), prompt \(p\), maximum reasoning steps \(T_{\max}\)
\ENSURE Routed trajectory \(y_{1:T}\), final answer \(a\), routing diagnostics
\STATE Initialize \(y_{<1}\gets\varnothing\)
\STATE Initialize pathway coefficients \(\gamma_1^{(\ell,h)}\gets 1\) for all routed heads
\FOR{\(t=1,2,\dots,T_{\max}\)}
    \STATE Generate reasoning sentence \(y_t\) under the current pathway \(\mathcal{P}_t\) and fixed strategy \(\pi\)
    \STATE Check whether the generated step reaches a sentence boundary
    \IF{a sentence boundary is reached}
        \STATE Extract layer-wise sentence readouts \(\{r_t^{(\ell)}\}_{\ell\in\mathcal{L}_{\mathrm{route}}}\)
        \FOR{each routed layer \(\ell\in\mathcal{L}_{\mathrm{route}}\)}
            \STATE Compute state activations \(q_t^{(\ell)}\gets \sigma(A^{(\ell)}r_t^{(\ell)}+b^{(\ell)})\)
            \STATE Compose routed coefficients
            \[
            \gamma_{t+1}^{(\ell,h)}\gets
            \mathrm{clip}\!\left(\sum_{k=1}^{K} q_t^{(\ell)}(k)\,m_k^{(\ell,h)},0,1\right),
            \qquad (\ell,h)\in\mathcal{H}
            \]
        \ENDFOR
        \STATE Instantiate the next pathway \(\mathcal{P}_{t+1}=\{\gamma_{t+1}^{(\ell,h)}\}_{(\ell,h)\in\mathcal{H}}\)
    \ELSE
        \STATE Keep the current routed pathway unchanged for subsequent token generation
    \ENDIF
    \IF{the external reasoning paradigm reaches its stop condition}
        \STATE \textbf{break}
    \ENDIF
\ENDFOR
\STATE Decode final answer \(a\) from the routed trajectory
\end{algorithmic}
\end{algorithm}

The key runtime property is low overhead: probe evaluation is triggered only at sentence boundaries, while pathway updates are obtained by lightweight template mixing over the cached artifact.

\subsection{Boundary-Triggered Routing Dynamics}
\label{app:alg_online_boundary}

LoTR updates routing only when a sentence step is completed. Between two sentence boundaries, the current pathway \(\mathcal{P}_t\) is kept fixed and is used for all subsequent token generation inside that step. This design matches the sentence-level control granularity of Sec.~\ref{sec:online}: it avoids token-level oscillation, keeps the controller stable, and makes the online cost independent of token-by-token routing updates.

\paragraph{Initialization.}
At the first reasoning step, all routed coefficients are initialized to \(1\), so the first sentence is generated under the unmodified backbone pathway. The first probe-and-route update is therefore triggered only after the first sentence boundary is reached, at which point LoTR instantiates \(\mathcal{P}_{2}\) for the next step.

\paragraph{Paradigm compatibility.}
The online controller is agnostic to the outer reasoning scaffold. Different paradigms may impose different stop rules, revision loops, sampling branches, or search states, but LoTR only requires access to the current sentence boundary, the corresponding layer-wise readouts, and the next-step generation interface. This is why the same offline artifact can be reused across heterogeneous reasoning paradigms on the same backbone.

\section{Why Existing Paradigms Can Underexplore the Frontier}
\label{app:theory_frontier}

This section formalizes the central claim of the paper: external reasoning paradigms can differ in trajectory mechanism while still sharing one limitation, namely the lack of explicit control over the relationship between dynamic logic state and internal computation pathway.

\paragraph{Setup.}
Fix an external reasoning strategy \(\pi\). Let the one-step utility under pathway \(\mathcal{P}_t\) be
\begin{equation}
J_t(\pi,\mathcal{P}_t)
=
\mathbb{E}[u_t \mid p,y_{<t};\pi,\mathcal{P}_t].
\label{eq:app_frontier_utility}
\end{equation}
Let \(k\in\{1,\dots,K\}\) index the recurring logic states. We write \(\tilde{\alpha}_t^\star(k)\) for the normalized state weights induced by the current step, so that \(\sum_{k=1}^K \tilde{\alpha}_t^\star(k)=1\). We use \(J_t(\pi,\mathcal{P}\mid k)\) to denote the same one-step utility conditioned on the current state \(k\).

For each state \(k\), define a state-optimal pathway by
\begin{equation}
\mathcal{P}_{t,k}^{\star}\in\arg\max_{\mathcal{P}}J_t(\pi,\mathcal{P}\mid k).
\label{eq:app_frontier_state_opt}
\end{equation}

\paragraph{Assumption D.1 (state-sensitive optimality).}
There exist two states \(k\neq k'\) with \(\tilde{\alpha}_t^\star(k)>0\) and \(\tilde{\alpha}_t^\star(k')>0\) such that no single pathway \(\mathcal{P}\) is simultaneously optimal for both states. Equivalently,
\[
\forall \mathcal{P},\quad
\exists j\in\{k,k'\}\ \text{such that}\ 
J_t(\pi,\mathcal{P}\mid j)<J_t(\pi,\mathcal{P}_{t,j}^{\star}\mid j).
\]

\paragraph{Assumption D.2 (External-only control).}
An external-only controller may vary the outer strategy \(\pi\), but for fixed \(\pi\) it uses one shared pathway rule \(\bar{\mathcal{P}}_t^{(\pi)}\) across all states and does not condition \(\mathcal{P}_t\) on the current state \(k\).

\paragraph{Proposition D.1 (Frontier underexploration under state mismatch).}
Under D.1--D.2, for fixed \(\pi\),
\begin{equation}
\mathbb{E}_{k\sim \tilde{\alpha}_t^\star}
J_t(\pi,\bar{\mathcal{P}}_t^{(\pi)}\mid k)
\;<\;
\mathbb{E}_{k\sim \tilde{\alpha}_t^\star}
J_t(\pi,\mathcal{P}_{t,k}^{\star}\mid k).
\label{eq:app_frontier_gap}
\end{equation}

\paragraph{Proof.}
For every state \(k\), by definition of \(\mathcal{P}_{t,k}^{\star}\),
\begin{equation}
J_t(\pi,\bar{\mathcal{P}}_t^{(\pi)}\mid k)
\le
J_t(\pi,\mathcal{P}_{t,k}^{\star}\mid k).
\label{eq:app_frontier_pointwise}
\end{equation}
Multiplying by \(\tilde{\alpha}_t^\star(k)\) and summing over \(k\) yields
\[
\mathbb{E}_{k\sim \tilde{\alpha}_t^\star}
J_t(\pi,\bar{\mathcal{P}}_t^{(\pi)}\mid k)
\le
\mathbb{E}_{k\sim \tilde{\alpha}_t^\star}
J_t(\pi,\mathcal{P}_{t,k}^{\star}\mid k).
\]
It remains to show strictness. By Assumption D.1, among the positive-mass states there exist \(k\neq k'\) such that no single pathway is optimal for both. Since \(\bar{\mathcal{P}}_t^{(\pi)}\) is shared across states by Assumption D.2, it must be strictly suboptimal for at least one positive-mass state \(j\in\{k,k'\}\). Hence
\[
J_t(\pi,\bar{\mathcal{P}}_t^{(\pi)}\mid j)
<
J_t(\pi,\mathcal{P}_{t,j}^{\star}\mid j),
\]
for some \(j\) with \(\tilde{\alpha}_t^\star(j)>0\). Therefore the weighted sum is also strict, giving Eq.~\eqref{eq:app_frontier_gap}. \(\square\)

\paragraph{Interpretation.}
This proposition does not deny the value of stronger external procedures. It shows instead that, even under a fixed external strategy, a controller that ignores state--pathway coupling can remain strictly suboptimal whenever different positive-mass logic states require incompatible optimal pathways.

\section{Why LoTR Improves Fixed Paradigms}
\label{app:theory_improve}

This section formalizes why LoTR can improve a fixed external reasoning strategy \(\pi\) without altering its outer program: the gain comes from better matching the internal pathway to the step-level logic state mixture currently induced by the trajectory.

\paragraph{Setup.}
Fix an external reasoning strategy \(\pi\). Let \(\tilde{\alpha}_t^\star\in\Delta^{K-1}\) denote the normalized ideal state mixture induced by the current reasoning step, and let \(\mathcal{P}_t^\star\) denote the corresponding state-optimal pathway under \(\pi\). Define the ideal template mixture
\begin{equation}
\widetilde{\mathcal{P}}_t
:=
\sum_{k=1}^{K}\tilde{\alpha}_t^\star(k) M_k,
\label{eq:app_improve_ideal_mix}
\end{equation}
and let
\[
\bar q_t:=\frac{1}{|\mathcal{L}_{\mathrm{route}}|}\sum_{\ell\in\mathcal{L}_{\mathrm{route}}} q_t^{(\ell)}
\]
be the layer-aggregated probe mixture. The LoTR pathway instantiated online is
\begin{equation}
\widehat{\mathcal{P}}_t
:=
\sum_{k=1}^{K}\bar q_t(k) M_k,
\label{eq:app_improve_hat_path}
\end{equation}
which abstracts the layer-wise routing rule in Eq.~\eqref{eq:lotr_routing} at the pathway level. For notational simplicity, this section indexes the pathway by the decision step it is intended to execute; thus \(\widehat{\mathcal{P}}_t\) should be read as the pathway instantiated from the current state mixture for the next generated reasoning step.

\paragraph{Assumption E.1 (Probe consistency).}
The aggregated probe prediction error is bounded:
\begin{equation}
\mathbb{E}\!\left[\|\bar q_t-\tilde{\alpha}_t^\star\|_1\right]\le \epsilon_q.
\label{eq:app_improve_probe_err}
\end{equation}

\paragraph{Assumption E.2 (Template approximation).}
The ideal state mixture over cached templates approximates the state-optimal pathway:
\begin{equation}
\mathbb{E}\!\left[\|\widetilde{\mathcal{P}}_t-\mathcal{P}_t^\star\|_1\right]\le \epsilon_m.
\label{eq:app_improve_template_err}
\end{equation}

\paragraph{Assumption E.3 (Pathway-Lipschitz utility).}
For fixed \(\pi\), one-step utility is \(L_u\)-Lipschitz in pathway:
\begin{equation}
|J_t(\pi,\mathcal{P})-J_t(\pi,\mathcal{P}')|
\le
L_u\|\mathcal{P}-\mathcal{P}'\|_1.
\label{eq:app_improve_lipschitz}
\end{equation}

\paragraph{Assumption E.4 (Bounded template mixing).}
The template mixing operator is \(L_M\)-Lipschitz with respect to the state mixture, i.e.,
\begin{equation}
\left\|
\sum_{k=1}^{K}\beta(k)M_k-\sum_{k=1}^{K}\beta'(k)M_k
\right\|_1
\le
L_M\|\beta-\beta'\|_1
\qquad
\forall \beta,\beta'\in\Delta^{K-1}.
\label{eq:app_improve_mix_lipschitz}
\end{equation}

\paragraph{Proposition E.1 (Additive approximation bound under fixed \(\pi\)).}
Under E.1--E.4,
\begin{equation}
\mathbb{E}[J_t(\pi,\widehat{\mathcal{P}}_t)]
\ge
\mathbb{E}[J_t(\pi,\mathcal{P}_t^\star)]
-
L_u\bigl(L_M\epsilon_q+\epsilon_m\bigr).
\label{eq:app_improve_bound}
\end{equation}
Hence, when \(L_M\epsilon_q+\epsilon_m\) is small, LoTR approaches state-optimal execution under the same fixed strategy \(\pi\).

\paragraph{Proof.}
By Assumption E.3,
\begin{equation}
J_t(\pi,\widehat{\mathcal{P}}_t)
\ge
J_t(\pi,\mathcal{P}_t^\star)
-
L_u\|\widehat{\mathcal{P}}_t-\mathcal{P}_t^\star\|_1.
\label{eq:app_improve_step1}
\end{equation}
Insert \(\widetilde{\mathcal{P}}_t\) and apply the triangle inequality:
\begin{equation}
\|\widehat{\mathcal{P}}_t-\mathcal{P}_t^\star\|_1
\le
\|\widehat{\mathcal{P}}_t-\widetilde{\mathcal{P}}_t\|_1
+
\|\widetilde{\mathcal{P}}_t-\mathcal{P}_t^\star\|_1.
\label{eq:app_improve_step2}
\end{equation}
For the first term, using the definitions of \(\widehat{\mathcal{P}}_t\) and \(\widetilde{\mathcal{P}}_t\) together with Assumption E.4 gives
\begin{equation}
\|\widehat{\mathcal{P}}_t-\widetilde{\mathcal{P}}_t\|_1
=
\left\|
\sum_{k=1}^{K}\bar q_t(k)M_k
-
\sum_{k=1}^{K}\tilde{\alpha}_t^\star(k)M_k
\right\|_1
\le
L_M\|\bar q_t-\tilde{\alpha}_t^\star\|_1.
\label{eq:app_improve_step3}
\end{equation}
Taking expectations and applying Assumptions E.1 and E.2 yields
\begin{equation}
\mathbb{E}\!\left[\|\widehat{\mathcal{P}}_t-\mathcal{P}_t^\star\|_1\right]
\le
L_M\epsilon_q+\epsilon_m.
\label{eq:app_improve_step4}
\end{equation}
Substituting Eq.~\eqref{eq:app_improve_step4} into Eq.~\eqref{eq:app_improve_step1} proves Eq.~\eqref{eq:app_improve_bound}. \(\square\)

\paragraph{Interpretation.}
Proposition~E.1 formalizes the mechanism claim in the main paper: LoTR does not need to alter the external reasoning trajectory to improve a fixed paradigm. Its gain comes from reducing the mismatch between the logic state mixture expressed by the current step and the internal pathway used to execute the next one.

\section{Why Logic States Generalize Across Problems and Paradigms}
\label{app:theory_generalize}

This section formalizes the design choice of pooling trajectories from multiple reasoning paradigms and fitting one shared probe family. The key claim is that if the geometry of state-conditioned readouts is sufficiently stable across paradigms, then a pooled probe can remain effective beyond the paradigms used for offline compilation.

\paragraph{Setup.}
Fix a routed layer \(\ell\in\mathcal{L}_{\mathrm{route}}\). Let \(r_t^{(\ell)}\in\mathbb{R}^d\) denote the sentence-level readout at step \(t\), and let \(k\in\{1,\dots,K\}\) denote the recurring logic state induced by the shared offline basis. Let \(\mathcal{D}_{\pi}\) denote the joint distribution of \((r_t^{(\ell)},k)\) under external reasoning strategy \(\pi\), and let
\[
\mathcal{D}_{\mathrm{pool}}
:=
\sum_{\pi} w_\pi \mathcal{D}_{\pi}
\]
be the pooled training distribution over paradigms. For a probe \(g:\mathbb{R}^d\to[0,1]^K\) and bounded loss \(\ell(g(r),k)\in[0,1]\), define
\begin{equation}
\mathcal{R}_{\pi}(g):=\mathbb{E}_{(r,k)\sim\mathcal{D}_{\pi}}\ell(g(r),k),
\qquad
\mathcal{R}_{\mathrm{pool}}(g):=\mathbb{E}_{(r,k)\sim\mathcal{D}_{\mathrm{pool}}}\ell(g(r),k).
\label{eq:app_gen_risk_def}
\end{equation}
Let \(\hat g_{\mathrm{pool}}\) denote a pooled risk minimizer (or its empirical approximation).

\paragraph{Assumption F.1 (Shared state geometry).}
For every state \(k\), the conditional readout distributions are stable across paradigms up to bounded shift:
\begin{equation}
\sup_{\pi,\pi'}\mathrm{TV}\!\bigl(p(r_t^{(\ell)}\mid k,\pi),\,p(r_t^{(\ell)}\mid k,\pi')\bigr)\le \delta.
\label{eq:app_gen_shift}
\end{equation}

\paragraph{Assumption F.2 (Shared state support).}
The target paradigm does not introduce logic states outside the pooled support, so both pooled and target risks decompose over the same state index set \(\{1,\dots,K\}\).

\paragraph{Proposition F.1 (Cross-paradigm transferability of a pooled probe family).}
Under F.1--F.2, for any target paradigm \(\pi'\),
\begin{equation}
\mathcal{R}_{\pi'}(\hat g_{\mathrm{pool}})
\le
\mathcal{R}_{\mathrm{pool}}(\hat g_{\mathrm{pool}})
+
\epsilon_{\mathrm{shift}}
+
\epsilon_{\mathrm{marg}}
+
\lambda^\star_{\pi'},
\label{eq:app_gen_bound}
\end{equation}
where \(\epsilon_{\mathrm{shift}}=O(\delta)\) controls state-conditioned geometry shift, \(\epsilon_{\mathrm{marg}}\) captures the mismatch between pooled and target state marginals, and
\begin{equation}
\lambda^\star_{\pi'}
:=
\inf_g\bigl(\mathcal{R}_{\mathrm{pool}}(g)+\mathcal{R}_{\pi'}(g)\bigr)
-
\inf_g \mathcal{R}_{\mathrm{pool}}(g)
\label{eq:app_gen_lambda}
\end{equation}
measures the approximation cost of using one shared probe family for both pooled and target distributions.

\paragraph{Proof.}
Conditioning on the state index,
\[
\mathcal{R}_{\pi'}(g)
=
\sum_{k=1}^{K}\Pr_{\pi'}(k)\,
\mathbb{E}_{r\sim p(r\mid k,\pi')}\ell(g(r),k),
\]
and likewise
\[
\mathcal{R}_{\mathrm{pool}}(g)
=
\sum_{k=1}^{K}\Pr_{\mathrm{pool}}(k)\,
\mathbb{E}_{r\sim p(r\mid k,\mathrm{pool})}\ell(g(r),k).
\]
The target--pooled risk gap can therefore be decomposed into two sources: (i) mismatch in the conditional readout geometry within each state, and (ii) mismatch in the state marginals themselves. Since \(\ell\in[0,1]\), the difference between two conditional expectations is bounded by twice the total variation distance between the corresponding conditional distributions. Assumption~F.1 therefore implies that the state-conditioned shift contributes at most an \(O(\delta)\) term, which we denote by \(\epsilon_{\mathrm{shift}}\). The discrepancy between \(\Pr_{\pi'}(k)\) and \(\Pr_{\mathrm{pool}}(k)\) contributes an additional marginal term \(\epsilon_{\mathrm{marg}}\). Finally, even under perfect distributional alignment, one shared probe family may not be simultaneously optimal for both pooled and target distributions; this residual approximation cost is captured by \(\lambda^\star_{\pi'}\). Applying the decomposition to \(g=\hat g_{\mathrm{pool}}\) gives Eq.~\eqref{eq:app_gen_bound}. \(\square\)

\paragraph{Interpretation.}
Proposition~F.1 justifies the pooled offline strategy of LoTR. If recurring logic states induce sufficiently stable readout geometry across paradigms and state support is shared, then one pooled probe family can remain effective beyond the paradigms used for compilation. This is why LoTR can pool heterogeneous reasoning trajectories offline, build one shared logic basis, and still reuse one probe/template system online.

\section{Datasets, Models, Paradigms, Metrics, and Protocol}
\label{app:exp_setup}

\paragraph{Datasets and task families.}
We evaluate on eight reasoning benchmarks also summarized in Table~\ref{tab:app_dataset_metric_map}.
\textbf{GSM8K} \citep{cobbe2021gsm8k} tests grade-school math word problems with integer answers.
\textbf{MATH} \citep{hendrycks2021math} targets competition-style mathematics with boxed answers.
\textbf{BoolQ} \citep{clark2019boolq} asks yes/no questions grounded in Wikipedia passages.
\textbf{HumanEval} \citep{chen2021evaluating} measures functional correctness on Python docstring-to-code synthesis.
\textbf{MMLU} \citep{hendrycks2021mathmassive} aggregates multiple-choice knowledge questions spanning STEM and humanities.
\textbf{FOLIO} \citep{han2022folio} evaluates natural-language deduction chains mapped to first-order logic judgments.
\textbf{HotpotQA} \citep{yang2018hotpotqa} requires multi-hop evidence fusion over Wikipedia paragraphs (we report F1 on span prediction).
\textbf{NarrativeQA} \citep{kocisky2018narrativeqa} asks reading-comprehension questions over full book/movie summaries with explicit-token answers scored by EM.
Unless noted otherwise, prompts and graders follow the dataset releases packaged with our evaluation code.

\paragraph{Backbone models.}
We evaluate \textbf{Llama-3.1-8B} \citep{grattafiori2024llama3}, \textbf{Qwen2.5-14B} \citep{yang2024qwen25}, and \textbf{Mixtral-8$\times$7B} \citep{jiang2024mixtral}.

\paragraph{Reasoning paradigms.}
LoTR is evaluated under eight \emph{external} scaffolds (including Vanilla).
\textbf{Vanilla} is greedy completion without an explicit reasoning recipe.
\textbf{Chain-of-Thought (CoT)} \citep{wei2022chain} elicits step-by-step rationales before an answer.
\textbf{Plan-and-Solve (PS)} \citep{wang2023plan} separates planning from execution for structured decomposition.
\textbf{Self-Refine (SR)} \citep{madaan2023selfrefine} iterates draft--critique--revise loops under a scripted program.
\textbf{Self-Consistency (SC)} \citep{wang2023selfconsistency} samples multiple chains and aggregates by majority vote.
\textbf{Best-of-$N$ (BoN)} \citep{chow2024inferenceaware,lightman2024verify} draws \(N\) candidates and reranks or selects the strongest finish.
\textbf{Constrained Beam (CB)} \citep{hokamp2017lexically,post2018fast} expands a bounded beam of hypotheses with lexical or structural constraints at each step.
\textbf{Monte Carlo Tree Search (MCTS)} \citep{xie2024mcts} budgets iterative expansion/scoring of partial reasoning states before committing to an answer.
LoTR never replaces \(\pi\): it only swaps internal attention pathways between sentence boundaries while \(\pi\) schedules decoding.

\paragraph{Metrics.}
We report benchmark-native accuracy (EM, F1, or Pass@1 as in Table~\ref{tab:app_dataset_metric_map}) and efficiency via average generated reasoning tokens plus wall-clock latency measured on NVIDIA H200 GPUs under a shared software stack. Reasoning tokens tally decoder completions attributable to the paradigm scaffold (excluding cached prompts where applicable); latency captures end-to-end wall time including probe/controller overhead for LoTR and analogous steering hooks for baselines.

\paragraph{Trajectory collection and offline pooling protocol.}
For offline compilation we pool sentence-level readouts from trajectories logged under the paradigms above, merge them into \(\mathcal{R}\), and fit one clustering/probe/template artifact per backbone.
No backbone weights are updated.

\section{Baselines}
\label{app:baselines}

\paragraph{Plug-in baselines.}
Besides raw paradigm runs, we compare against inference-time steering methods that keep weights frozen.
\textbf{Inference-Time Intervention (ITI)} \citep{li2023inference} applies additive activations along selected attention-head directions discovered from contrastive pairs.
\textbf{Activation Addition (ActAdd)} \citep{turner2024actadd} steers generations by injecting fixed activation offsets during forward passes.
\textbf{STIR} \citep{shi2026stir} retrieves latent steering impulses conditioned on the ongoing trajectory rather than using a single static vector.
\textbf{RISER} \citep{ye2026riser} routes among multiple reusable steering experts so impulses adapt to inferred reasoning regimes.

\paragraph{Why this baseline set is sufficient.}
These families respectively cover head masking/addition, global offsets, retrieval-conditioned impulses, and routed mixtures---complementary axes of inference-time control---while remaining comparable to LoTR in compute regime (no weight updates).

\section{Pipeline Step-wise Effect}
\label{app:pipeline_effect}

LoTR depends on a two-stage mechanism: the offline stage must recover a compact set of stable logic states from sentence-level readouts, and the online stage must use these states to induce differentiated head-routing patterns during reasoning. We therefore analyze the pipeline at both levels. First, we examine clustering quality and state-conditioned head importance across \(K\in\{2,3,4,5\}\). Second, using the deployed \(K{=}5\) artifact, we analyze step-resolved and benchmark-averaged state mixtures induced by different external reasoning paradigms.

\subsection{Offline stage effects: clustering quality and head importance}
\label{app:pipeline_effect_offline}

\paragraph{Cluster geometry for \(K{=}2,\dots,5\).}
Increasing \(K\) improves local resolution but also raises the risk of fragmenting coherent modes or assigning thin empirical support to individual clusters, which would destabilize both soft targets and template estimates. Figure~\ref{fig:app_k_sweep} summarizes the sweep over the pooled readout bank. Across the tested values, \(K{=}5\) provides the best operating point: the clusters remain visually separated while further splits mainly subdivide already coherent regions. This supports the deployed cardinality as a compact but expressive logic-state basis rather than an arbitrary hyperparameter choice.

\paragraph{State-conditioned head importance for the same sweep.}
Embedding-space separability is useful for LoTR only if the recovered states correspond to different computation pathways. Figure~\ref{fig:app_head_importance_offline} aligns the \(K\)-sweep with per-cluster head-importance maps. The maps show that clusters at the same \(K\) induce distinct layer--head salience patterns, while refinements across \(K\) preserve recognizable structure rather than producing arbitrary relabeling. Thus, the offline stage does not merely produce centroids in representation space; it produces empirically grounded indices into reusable head-level pathways, enabling the template bank to specialize \(\gamma\) without modifying backbone weights.

\subsection{Online stage effects: paradigm-specific cluster mixtures at \(K{=}5\)}
\label{app:pipeline_effect_online}

\paragraph{Step-resolved state marginals.}
Figure~\ref{fig:app_step_state_marginals} traces the trajectory-level proximity to the deployed PCA\textsubscript{3} \(K\)-means centroids over sentence index \(t\le30\) for each outer paradigm \(\pi\). Unlike pooled histograms, these curves expose how state mass evolves within a rollout. Different paradigms exhibit distinct temporal profiles even under the same \(K{=}5\) state basis, indicating that the recovered states are repeatedly revisited and recombined during reasoning rather than acting as static dataset labels.

\paragraph{Pooled mixtures across benchmarks.}
If the \(K{=}5\) states were spurious, the online histograms would remain nearly invariant across external paradigms. Figure~\ref{fig:app_cluster_mixture_online} argues against this degenerate interpretation. We aggregate sentence-boundary assignments from the online probes across evaluation traces, average the histograms over benchmarks, and obtain one mixture vector per paradigm. The resulting profiles differ substantially across \(\pi\), while no single state dominates all paradigms. Moreover, paradigms that emphasize exploration or verification place more mass on states whose offline salience maps already show differentiated head usage. This links the online behavioral mixtures back to the offline pathway templates and supports the claim that LoTR reuses a shared logic basis in paradigm-specific ways.

The intended reading is threefold. First, mass shifts across \(\pi\) while \(K\) is shared, supporting reusable latent modes rather than singleton artifacts. Second, no cluster dominates uniformly, arguing against degenerate everything collapses to one centroid failures at \(K{=}5\). Third, histogram contrasts remain consistent with Figure~\ref{fig:app_head_importance_offline}---paradigms that stress exploration or verification lean toward clusters whose offline salience maps already differentiate heads---which stitches behavioral mixtures back to the offline sweep.

\subsection{Efficiency results on Qwen2.5-14B and Mixtral-8x7B}
\label{app:extra_eff}

Table~\ref{tab:app_eff_qwen} and Table~\ref{tab:app_eff_mixtral} quantify the efficiency side of the Qwen and Mixtral results. Relative to the unsteered paradigms, LoTR reduces average token usage by \(2.28\%\) on Qwen2.5-14B, but increases latency by \(72.08\%\). In contrast, on Mixtral-8$\times$7B, token usage is essentially unchanged \((+0.22\%)\), while latency decreases by \(12.15\%\). Thus, the accuracy gains are not driven by longer generations, but the wall-time cost is backbone-dependent. This distinction is important for deployment: LoTR can improve the accuracy--token frontier consistently, while latency depends on the cost of inserting the controller into a particular inference stack.

\paragraph{Accuracy--efficiency trade-off.}
Figure~\ref{fig:tradeoff_appendix_qwen_mixtral} summarizes the same pattern as a two-objective trade-off. LoTR moves both backbones toward higher accuracy with little change in generated length, while bubble size exposes the backbone-specific latency behavior: substantial overhead on Qwen2.5-14B but runtime reduction on Mixtral-8$\times$7B. The figure therefore separates two effects that are easy to conflate in tables: LoTR's gains do not come from generating more tokens, but the realized wall-time cost depends on the inference stack.

On Mixtral--FOLIO, removing state-conditioned routing drops performance from \(24.5\) to \(21.0\), a \(14.29\%\) relative decrease. \AppBlock{Part E: Limitations and Discussion}

\section{Limitations}
\label{app:limitations}

\paragraph{Practical value and impact scope.}
LoTR targets a practical deployment setting where backbone weights and external reasoning scaffolds are fixed, but inference quality/efficiency still need improvement. In this scope, the method can reduce trial-and-error cost when integrating reasoning wrappers and can improve reliability on selected reasoning-heavy tasks.

\paragraph{Method-level limitations.}
\begin{itemize}[leftmargin=1.6em]
    \item \textbf{Dependence on offline trajectory coverage.} Logic-state discovery is built from pooled trajectories; if rare reasoning modes are weakly represented, routing quality may degrade.
    \item \textbf{Granularity trade-off in \(K\).} Smaller \(K\) is generally more stable but may merge distinct reasoning states; larger \(K\) can increase specificity but may introduce variance and over-fragmentation.
    \item \textbf{Backbone-specific artifacts.} The current artifact (probes/templates) is compiled per backbone and is not guaranteed to transfer directly across model families.
\end{itemize}

\paragraph{Experimental limitations.}
\begin{itemize}[leftmargin=1.6em]
    \item \textbf{Backbone and task scope.} Experiments focus on three open backbones and eight reasoning-centered benchmarks; broader generation tasks and additional closed-model APIs are not yet systematically covered.
    \item \textbf{Compute-budget constraints.} Some analyses prioritize breadth of settings over repeated-run statistics because full factorial reruns across all paradigms and backbones are expensive.
\end{itemize}

\paragraph{Deployment limitations.}
\begin{itemize}[leftmargin=1.6em]
    \item \textbf{Boundary dependence.} Sentence-level routing assumes stable step boundaries; if the generation format is irregular, routing updates can become less reliable.
    \item \textbf{Overhead still exists.} Although lightweight relative to full decoding, LoTR introduces additional probe/template computation and offline compilation cost.
    \item \textbf{No replacement for task-level safeguards.} LoTR optimizes internal routing, but application-level validation, safety filtering, and human oversight remain necessary for high-stakes use.
\end{itemize}

\section{Future Work}
\label{app:future}

\begin{itemize}[leftmargin=1.6em]
    \item \textbf{Uncertainty-aware routing.} Add calibrated uncertainty signals so low-confidence state estimates trigger conservative routing updates.
    \item \textbf{Broader robustness evaluation.} Extend evaluation to more out-of-domain tasks, longer-context settings, and stronger closed-model APIs.
    \item \textbf{Efficient repeatability studies.} Add targeted repeated-run protocols (e.g., selected paradigms/datasets) to complement broad-coverage single-run reporting.
    \item \textbf{Cross-backbone alignment.} Study partial transfer of logic states/templates across related backbones to reduce per-backbone compilation cost.
\end{itemize}
